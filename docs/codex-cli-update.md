# 在页面更新 Codex CLI

打开目标机器的详情页，在 **Codex CLI** 区域查看版本、更新状态和模型说明。默认设置页选择 Codex 后，也可通过“更新 Codex CLI 与模型列表”进入对应机器；链接副标题会注明机器名称。

点击“更新 CLI”会更新这台机器上由 Hapla 启动的 Codex，并同步模型列表与推理档位说明。操作只作用于选中的机器，不更新其他机器，也不升级 Hapla CLI、前端或服务器本身。只需重新读取模型能力时，点击“刷新模型与档位”即可，无须安装新版本。展开“模型与档位说明”可以查看该机器当前返回的完整说明和默认档位。

## 更新如何执行

页面把任务交给目标机器的 Hapla daemon，依次显示检查版本、安装、验证和同步模型的进度。同一 daemon 同时只执行一个更新任务。离开页面或关闭浏览器不会取消已经提交的任务；重新进入机器详情页会继续读取状态。连接中断只代表状态暂时无法确认，可点“重试”重新读取，不能据此判断安装失败。

支持的安装会从官方 npm registry 查询 `@openai/codex` 的最新稳定版本，并下载到 Hapla 自己管理的独立目录。安装不会覆盖原来的全局 npm 包；先核对版本，再启动候选版本的 app-server，验证 `model/list` 能返回可用模型，随后原子切换当前版本指针。当前版本已相同或更高时，只同步模型，不降级。

每个托管版本都有独立目录，已经运行的 Codex 进程继续使用原来的文件。新版本用于后续启动的 Codex；仅刷新浏览器不会替换正在执行任务的进程。安装或验证失败时继续使用原版本；切换后的模型同步失败时尝试恢复原指针。若恢复本身失败，页面会明确报告，不能当作已回滚成功。daemon 在更新中重启后，未确认完成的任务会显示失败，便于重新检查。

## 模型与档位来源

模型名称、模型说明、支持的推理档位及每档说明均来自实际选用的 Codex app-server 的 `model/list`，会读取全部分页。页面保留 CLI 提供的原始说明，不根据版本号猜测模型或编写固定的档位介绍。

更新只有在新目录成功发布给服务器后才显示完成。新建会话、默认设置和会话内选择器优先使用机器最新上报的目录，避免旧会话启动时保存的列表盖住新结果。强制刷新失败或返回空模型时保留上次的列表，并报告同步失败；技能读取单独失败时，仍可同步模型，同时保留原有技能列表。

## 安装范围与运维

页面更新支持 Linux、macOS 上的官方 npm、定制二进制和其他安装方式，机器需要可用的 npm 和网络。点击“更新 CLI”会安装官方 npm 版本并让 Hapla 后续启动的 Codex 使用它；定制版本原文件保留，原补丁不会带入官方版本。当前 Windows 安装仍需使用本机包管理器更新，页面可单独刷新模型。

托管数据位于 `$HAPLA_HOME_DIR/tools/codex`；没有配置 `HAPLA_HOME_DIR` 时为 `~/.hapla/tools/codex`。其中 `current.json` 指向当前托管版本，`update.json` 保存更新任务状态，`releases/` 保留已安装版本。容器应持久化对应的 Hapla 数据目录，才能在重建后保留版本选择与任务记录。运行中的进程可能仍使用旧版本目录，清理旧文件前应确认相关进程已经退出。

如果页面提示 Hapla CLI 不支持该接口，需要先升级目标机器的 Hapla CLI；“更新 CLI”按钮更新的是 Codex，无法替代这一步。
