# Codex 服务端错误后的会话恢复

触发条件：Codex 发出权威终止事件，当前 turn 标记为失败，错误属于服务端故障。包括 `internalServerError`、`serverOverloaded`、HTTP 5xx，以及旧版本将 HTTP 200 SSE 内部错误归为 `other` 时的原始错误文案。

此前，`sendTurnContentAndWait` 会把失败 turn 当作正常完成，Hapla 继续复用旧进程。现在等待接口抛出 `CodexTurnFailure`，保留原始错误、thread/turn 关联和恢复结果；失败不会进入正常完成的媒体交付路径。

符合条件时，每次失败仅尝试一次恢复：

1. 等待已有原生命令清理完成，再关闭旧 Codex 进程。
2. 先确认旧进程已退出，避免两个进程同时写同一个对话。退出等待最多 5 秒；原来的 2 秒强制结束兜底仍然有效。
3. 重新选择当前安装的 Codex 可执行文件；构造客户端时传入的明确可执行文件参数仍保持固定。
4. 通过 `thread/resume` 恢复同一对话，保留当前模型、工作目录、原有权限与 MCP 配置。历史重建与自动压缩由 Codex 自身处理。

不自动重发已提交的业务请求，也不回滚对话或重跑工具。恢复成功后，用户直接发送下一条消息即可继续。恢复失败保留原始对话 ID，明确报告失败，不通过 `thread/start` 创建空白对话。

认证、配额、速率限制、参数错误、上下文超限、用户中断和未确认的连接断开不会触发这一恢复策略。服务端仍在重试的非终止错误也不会触发。恢复期间排队输入等待同一恢复操作，不抢先启动新 turn。原 turn 的等待超时在终止后取消，不会污染新进程状态。

此补丁修复本项目的失败识别和恢复行为，不能消除 OpenAI 服务端故障，也不能据此认定其内部根因。已运行的 Hapla 会话需要在下次启动或唤醒时加载新构建的代码。

验证：`codexAppServerClient.test.ts` 与 `codexTurnFailure.test.ts` 覆盖终止失败、旧版 SSE 错误、恢复次数、安装版本更新、退出等待、原对话与配置保留、业务请求不重发、恢复失败、过早终止通知和错误分类；现有长时间压缩与中断测试同时运行。
