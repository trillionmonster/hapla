# 视频卡片与浏览器缓存

2026-09-11 实施。对话列表不挂载 video 元素，不读取视频头、不预加载相邻视频。卡片固定封面比例和信息区高度，元数据到达后不改变卡片高度。接近视口时才请求封面与信息，浏览器最多同时读取两份元数据。

卡片展示小封面、总时长、原视频显示尺寸（考虑旋转）、宽高比和原文件大小。大小来自原文件 stat，不是封面大小；下载保持原始文件字节。自有服务器上传的视频通过原有账户权限检查后的 `/files/<path>?preview=video` 返回信息和小 JPEG；工作区视频通过所属 CLI 的 `getVideoPreview`，旧的运行中 CLI 可调用独立 `hapla-video-preview` 工具，避免中断运行任务。服务器封面最长 320×180，CLI 最长边 320；只生成一帧，不转码原视频。

点击卡片后才创建播放器，播放器 `preload=none`，点击播放才开始读取自有上传视频。关闭、切换视频、页面隐藏时暂停播放并移除 src/load，释放解码器与缓冲。

原视频缓存与小封面缓存分开管理：

- 自有服务器上传的视频使用 HTTP Range 和 Cache-Control: no-store，应用不持久缓存原视频。
- HTTPS 工作区视频优先按范围读取，不完整缓存原文件。
- HTTP 工作区视频按现有 RPC 分段准备，仅在用户打开时执行。浏览器 IndexedDB 跨标签页统一最多保留最近打开的 5 个工作区原视频，总容量最多 128 MiB；超出容量的大视频关闭后完全释放。
- 关闭播放器撤销 Blob URL；持久缓存写入成功后删除临时分段副本。第六个缓存会真实删除最旧数据，并通知其他标签页释放相应视频源。
- 会话卸载清理对应缓存；退出或切换账户清空所有原视频和封面缓存。
- 小封面及元数据最多 64 条，不包含原视频字节。失败结果短暂保留并可手动刷新。

外部网站的视频没有通用的封面与元数据接口，列表不会为了探测信息下载外站原视频。未知信息明确显示未知，打开后尽可能补充浏览器可读取的信息。外站自身 HTTP 缓存策略不由 Hapla 控制。

HTTP 工作区视频首次打开仍需完成分段准备；此过程已从打开会话、滚动列表移到明确打开视频之后。自有上传视频不受这一限制。
